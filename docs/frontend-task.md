# Frontend タスク整理

## 1. このドキュメントの位置づけ

- 本ドキュメントは、frontend 側で今後検討・実装が必要な項目をメモとして残すためのものです。
- 未確定の内容は「検討事項」、実装が必要な内容は「作業タスク」として扱います。
- 要件が固まった項目は、今後 `apps/frontend/README.md` や関連設計ドキュメントへ昇格させます。

## 2. 今回残すタスク

### 2.1 Eメールサインアップの有効 / 無効切替オプション

- Email サインアップ機能を、環境や運用方針に応じて `有効 / 無効` を切り替えられるようにする。

## 3. 検討事項

### 3.1 切替の責務をどこに置くか

- frontend 側で単純に UI を隠すだけにするか
- backend の設定 / API 応答を正として frontend が表示を切り替えるか
- frontend / backend の両方で制御するか

推奨の考え方:

- backend 側を正とし、frontend はその状態に追従して表示制御する。
- frontend だけで無効化すると、URL 直打ちや API 直呼び出しで不整合が出るため、表示制御だけで完結させない。

### 3.2 何を切り替えるか

- サインアップ導線リンクの表示
- サインアップページへの到達可否
- サインアップフォームの submit 可否
- 必要なら LP 上の訴求文言

### 3.3 UX 方針

- 無効時に、リンク自体を消すか
- クリック時に「現在利用できません」を表示するか
- `/signup` に直接来た場合に
  - ログインへリダイレクトするか
  - 専用メッセージを出すか

## 4. 作業タスク

### 4.1 frontend 側の表示制御

- サインアップ導線の表示を条件分岐できるようにする。
- 対象候補:
  - ログイン画面
  - LP
  - 認証導線コンポーネント

### 4.2 サインアップページのガード

- `apps/frontend/app/routes/signup.tsx` で、サインアップ無効時の挙動を定義する。
- 候補:
  - ログイン画面へ遷移
  - 案内文を表示して submit を無効化

### 4.3 API エラー時のハンドリング

- backend 側がサインアップ無効を返した場合に、frontend でも適切にメッセージを出せるようにする。
- `api-helper.ts` のエラーコード処理との整合を確認する。

### 4.4 i18n 文言の追加

- 無効時に表示する説明文言を `common` または auth 系 namespace に追加する。
- 日英で同じ条件分岐ができるようにする。

### 4.5 テスト追加

- サインアップ有効時:
  - 導線が見える
  - ページへ遷移できる
- サインアップ無効時:
  - 導線が隠れる、または無効表示になる
  - `/signup` 直アクセス時の挙動が仕様どおりになる

## 5. 推奨実装順

1. backend 側を正にするかどうかの方針を確定する
2. frontend の表示切替条件を決める
3. サインアップページ直アクセス時の UX を決める
4. UI 実装
5. i18n 追加
6. テスト追加

## 6. 要件へ昇格する条件

- 有効 / 無効の判定元が確定していること
- 無効時の UX（非表示 / メッセージ / リダイレクト）が確定していること
- backend との契約が固まっていること
- テスト観点が整理されていること
